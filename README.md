# AI Coding Notes

本仓统一管理 AI Coding 工具实践、概念与原理、Agent 相关学习、独立实验及必要的实践项目。目录用于组织已有内容，不构成必须完成的课程。

围绕理解陌生代码库、拆解任务、管理上下文、审查代码、设计测试和分析失败，按需补充概念并保留可迁移的方法。当前协作规则见 [AGENTS](AGENTS.md)。

## 学习与收录原则

- 目录只用于归档，项目问题决定学习顺序；前置知识补到够用，有实质内容再建目录，不追求课程或术语全覆盖。
- 重要单元围绕问题、必要讲解、实践、核验与复盘推进；用小变式或故障检查迁移，真实项目任务可替代重复的独立实验。
- 基础概念与工具机制学到够用，遇到实际问题再补充；验收关注任务定义、必要上下文、修改检查、有效测试、关键代码解释和变式或故障处理。
- 独立实验的解释与复盘留在知识笔记，材料和代码放入 Labs，双向链接；真实项目的源码与测试留在原仓库。
- 允许使用 AI；内容整理、系统产出与个人掌握分别记录，系统完成任务不自动证明个人已经理解。个人掌握状态保存在本地计划。
- 同一完整正文只维护一处，其他位置引用；不以术语、链接或文档数量衡量进度。
- 经案例支持的方法先在相关主题集中总结；分类与拆分按 Notes 索引的规则处理，不预建 Patterns、agents 等空目录。

## 环境与边界

默认在 Windows 维护笔记并进行适合的实验，Codex 是主要实践工具。笔记围绕项目需要的可迁移方法组织，产品操作单独维护；真实项目遵循原项目环境，Linux 相关任务在对应 Linux 环境完成。

本仓库聚焦 AI 如何参与软件工程，不收纳完整机器学习课程或产品功能大全。Building Agents、Mini Agent 和复杂 Agent 实现仍在 Backlog，有实际需求再评估恢复。

为学习 AI Coding／Agent 而独立建立的实验或实践项目，在本仓保存其实现与验证；AI 参与 RaftKV 等既有项目时，项目源码和完整证据留原仓，本仓仅记录可迁移的协作认识。不会因为新增 Agent 主题默认拆出新仓库，也不会因确定归属就自动启动实现。

当前 Notes 的 01、02 主题已有正文，03–06 仅为已有规划；Labs 已有端口实验，Tools 已有 Codex 入口，Sources 已有来源清单。独立 AI/Agent 实践优先按实际内容进入 Labs；若未来项目明显超过实验定位，再考虑本仓内 projects/，当前不建立或预留空入口。私人本地计划与 research.local 历史研究保留，不作为公开正文依赖。
