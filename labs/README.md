# Labs：实验索引与规范

保存独立实验的材料、代码、复现步骤和验收说明，也可索引真实项目任务的协作方法与证据。解释与完整复盘在相关知识笔记维护，本目录链接引用；真实项目源码与测试留在原仓库。

当前尚无实验实例。开始对应单元时再创建实验目录，不预填成功记录。

## 实践层次

| 层次 | 目的 | 示例 |
| --- | --- | --- |
| Tiny 实验 | 看清一个机制 | 上下文选择、一次工具调用、循环停止 |
| 独立变式 | 检查能否迁移 | 更换输入、材料或约束后自主完成 |
| 故障排查 | 理解条件与边界 | 缺失依据、错误参数、工具失败、无效测试 |
| 综合任务 | 组合知识完成实际目标 | 小型修复、日常开发任务验收 |
| 真实项目任务 | 在项目约束下验证协作能力 | 修复缺陷、补足测试、实现小功能并审查差异 |

各层次按问题选择，不是必须逐项完成的流程。项目任务已提供相应证据时，可替代重复独立实验；Tiny 实验用于隔离机制、补足证据或复现故障。

## 一次实践应说明什么

- 问题与关联知识：要检验什么，不预设某种方法必然有效。
- 环境与基线：客户端/版本、模型可见信息、初始材料与恢复方式；未知项如实标明。
- 输入与范围：任务文本、允许读取和修改的内容。
- 预测与变量：运行前的判断；比较时说明改变了什么、保留了什么。
- 执行方式：可复现的步骤或命令；本节需要的前置工具。
- 验收与实际结果：检查条件、真实产物、失败情况和必要证据。
- 变式与限制：哪些结论可迁移，哪些尚未验证。

独立实验开始实现时通常先建 README，按需增加 fixtures、src 和 tests；不固定要求每个实验都具备这些子目录。真实项目任务直接在原仓库开展，不在此复制项目或重复建立测试目录。

## 验收与证据

| 能力 | 可检查的证据 |
| --- | --- |
| 定义任务 | 目标、允许范围、约束和完成条件明确 |
| 提供必要上下文 | 能选择相关文件、接口约定和错误信息，并解释选择依据 |
| 检查修改 | 能阅读差异，识别越界修改、遗漏及潜在影响 |
| 运行有效测试 | 测试覆盖任务风险及必要边界或失败场景，能解释覆盖范围与局限 |
| 解释关键代码 | 能说明关键逻辑、数据流和设计选择，允许查阅资料 |
| 处理小变式或故障 | 约束变化或故障出现后，能组织定位、修改并重新验证 |

根据任务选择适用项并说明未覆盖项；只读或无代码任务不编造代码测试证据。系统产出记录实际修改、运行命令、测试结果及限制；个人掌握单独记录解释、判断、变式表现和所需帮助，保存在本地计划。

项目证据应定位到相关提交、文件、测试或复盘；已提交内容优先使用固定提交链接，并注明实际验证的版本。尚未提交的结果如实标注，不冒充已提交版本。避免只链接项目首页。私人证据只留在本地计划，公开笔记不依赖被忽略的文件。

## 判定原则

优先使用行为测试、断言、文件差异、可定位来源、工具返回与最终状态。开放性部分采用明确检查表，AI 点评只作补充。

系统成功与个人掌握分别判断。个人检查包括核心理解、允许查阅的应用，以及不由教学助手逐步指挥的迁移；可根据任务正常使用 AI。

结果符合约束时，不因采用另一种有效步骤判失败；仅在本节专门训练某个机制时检查相应过程。不能从表面输出推断不可观察的模型内部机制。

比较实验尽量固定初始环境与其他条件，记录所有实际尝试。少量重复用于暴露波动，不将三次成功写成普遍可靠；旧任务检查回归，新任务检查迁移。

## 数据与运行产物

独立实验使用明确的实验目录、模拟材料与最少必要数据。真实项目实践在获授权的原仓库和原项目环境开展，不自动开放其他仓库或私人档案。写入与命令执行遵守当次任务范围。

原始运行输出放 runs 或 work，已配置 Git 忽略。值得保留的脱敏证据单独整理后再纳入版本管理；不提交密钥、真实私人材料或完整聊天流水账。
